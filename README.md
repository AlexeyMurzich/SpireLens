# SpireLens

Локальная аналитика ваших забегов Slay the Spire 2. Версия 1.1.0 — самостоятельное оконное приложение для Windows 11 x64 (также Windows 10 22H2).

Для обычного пользователя: используйте установщик `SpireLens-1.1.0-Windows-x64-Setup.exe` или переносную ZIP-версию. Python, браузер и интернет не требуются. Подробности — `WINDOWS-README.txt`. Готовые бинарные файлы распространяются отдельно от исходников.

Исходники: `desktop.py` — окно приложения; `analyzer.py` — данные и аналитика; `app.py` и `static/` — сохранённая прежняя браузерная версия.

## Запуск

Установите Windows-версию через Setup.exe, затем откройте SpireLens из меню «Пуск». Переносная версия: распакуйте ZIP целиком и запустите SpireLens.exe.

Запуск исходников требует Python 3.10+ с Tkinter: `python desktop.py` или **Start.cmd**. На macOS — см. раздел «Запуск на macOS (из исходников)».

Сборка: используйте Windows x64 Python 3.12+ с Tkinter, установите зависимости командой `python -m pip install -r requirements-build.txt` и установите Inno Setup 6. Затем выполните `.\build-windows.ps1 -Python <python.exe> -InnoCompiler <ISCC.exe>`. Скрипт создаёт EXE в `dist/SpireLens/`, установщик и ZIP в `release/`. Сборка проверена с Python 3.12.14, PyInstaller 6.22.3 и Inno Setup 6.7.3.

Все вычисления выполняет Python внутри EXE; нативное окно построено на Tkinter. Оконная версия не запускает браузер и не открывает сетевой порт. Прежняя браузерная версия запускается отдельно через `python app.py` и слушает только 127.0.0.1. Данные не отправляются в интернет, сохранения не изменяются. Сервис автоматически перечитывает историю каждые 15 секунд; интерфейс обновляется, когда не открыт подробный разбор или поиск.

## Запуск на macOS (из исходников)

Установщик `Setup.exe` и переносной ZIP предназначены только для Windows. Готового приложения для macOS нет: на Mac SpireLens запускается из исходников.

1. Нужен Python 3.10+ с рабочим Tkinter (Tk 8.6 или новее). Системный `/usr/bin/python3` обычно слишком старый (Python 3.9 и Tk 8.5) и не подходит. Подойдёт Python с [python.org](https://www.python.org/downloads/macos/), Homebrew (`brew install python-tk@3.12`, затем запуск через `python3.12`) или [uv](https://docs.astral.sh/uv/). Проверка: `python3 -c "import tkinter; print(tkinter.TkVersion)"`.
2. В папке репозитория выполните `python3 desktop.py` (или `uv run --python 3.12 desktop.py`). Сторонние библиотеки не нужны.

Пути по умолчанию на macOS:

- История: `~/Library/Application Support/SlayTheSpire2/steam/<SteamID>/profileN/saves/history/*.run`.
- Русские названия: `~/Library/Application Support/Steam/steamapps/common/Slay the Spire 2/SlayTheSpire2.app/Contents/Resources/Slay the Spire 2.pck`. Дополнительные библиотеки Steam читаются из `~/Library/Application Support/Steam/steamapps/libraryfolders.vdf`.
- Настройки: `~/Library/Application Support/SpireLens/settings.json`. Другую папку настроек задаёт `--config-dir`.

Если история или названия не найдены, нажмите «Папка сохранений» и выберите `SlayTheSpire2`, папку Steam-профиля или `history`. Для названий нажмите «Файл игры / названия» и выберите `.pck`: он лежит внутри пакета приложения, поэтому в окне выбора нажмите ⌘⇧G и вставьте путь к папке `SlayTheSpire2.app/Contents/Resources`. Выбор сохраняется в настройках. Пути можно указать и при запуске:

```text
python3 desktop.py --data-dir "$HOME/Library/Application Support/SlayTheSpire2" --pck "/путь/к/Slay the Spire 2.pck"
```

## Что доступно

- Фильтры профиля, персонажа, вознесения, режима, команды, результата, дат, версии и минимального этажа.
- Процент побед, время, средний этаж, результаты по сложности и персонажам, последние 80 забегов на графике.
- Разбор забега: здоровье, полученный урон, комнаты, предложения карт, выборы, полученные/удалённые/улучшенные карты, реликвии, зелья и золото.
- Частота выбора карт, результаты забегов после выбора, реликвии в финальном инвентаре.
- Средний и общий урон по встречам, число ходов и причины поражений.
- Экспорт CSV текущей выборки (UTF-8 с BOM, разделитель `;`, совместим с Excel).
- Источники и ошибки чтения в отдельном разделе.

## Откуда берутся данные

Основной источник — `%APPDATA%\SlayTheSpire2\steam\<SteamID>\profileN\saves\history\*.run`: JSON-история завершённых забегов. Есть дата, длительность, персонаж, сложность, seed, исход, колода, инвентарь и `map_point_history` с решениями и состоянием после каждого узла.

Приложение ищет историю рекурсивно, но читает только `.run` в папках `history`. `.backup`, логи, служебная телеметрия и реплеи не читаются. Незавершённый забег появится после записи истории игрой. История не содержит полного порядка розыгрыша карт или каждого действия по ходам — таких выводов приложение не делает.

Русские названия читаются непосредственно из `SlayTheSpire2.pck` установленной игры. Игра ищется в Steam и дополнительных библиотеках из `libraryfolders.vdf`. Графические ресурсы не извлекаются. Поддержан открытый формат Godot PCK v2/v3; описание проверено по [исходникам Godot 4.5](https://github.com/godotengine/godot/blob/4.5/core/io/file_access_pack.cpp). Если словарь недоступен, используются читаемые внутренние идентификаторы.

## Как считаются результаты

Победа: `win=true`. Поражение: обычное завершение без победы и без флага прерывания. При флаге прерывания поражение предположительно определяется по финальному HP ≤ 0 при max_hp > 0, кроме перезапусков у Неоу. Поле killed_by само по себе не используется как доказательство смерти: у прерванных забегов оно бывает заполнено при положительном HP. Прерван: прерывание без надёжных признаков смерти. Неоу (EVENT.NEOW) при флаге прерывания считается перезапуском, даже если игра записала нулевые HP. Поражения при was_abandoned=true определяются по косвенным признакам и отмечены звёздочкой: это предположение, а не отдельный достоверный исход из игры. В локальной истории `was_abandoned` иногда стоит и при нулевом HP: поэтому флаг показывается отдельно и не скрывает поражение.

Процент побед = победы / **все** забеги текущей выборки, включая выходы. Фильтр «Исключить флаг прерван» исключает именно исходный `was_abandoned`, включая такие поражения. Чтобы убрать только выходы без смерти, выберите результат «Победы и поражения (*)».

Профили не смешиваются по умолчанию; автоматически выбран профиль с самым новым забегом. В кооперативе данные игрока выбираются по SteamID владельца папки. Файлы с неопределимым владельцем пропускаются с объяснением. Одиночная игра и обычный режим выбраны по умолчанию.

Карты: каждый забег учитывается один раз для предложения и выбора карты. Процент побед после выбора — связь с исходом, а не доказательство силы карты. Полученные из событий, магазина и начальной колоды карты не входят в показатель выбора из награды, но видны в разборе и финальной колоде. Реликвии считаются по финальному инвентарю. Длинные забеги имеют больше возможностей получить реликвии: их процент побед не является рейтингом.

Этаж — последовательный номер посещённого узла в истории, включая Древнего. Урон — сумма `damage_taken` вашего игрока. Ходы — `turns_taken` комнаты; в кооперативе это длительность комнаты команды. При нескольких боях в одном узле они показаны вместе, чтобы не дублировать урон.

Игра обновляется: проверены локальные схемы истории 9 и 10. Неизвестные дополнительные поля игнорируются; ошибки файлов показаны в интерфейсе, не прерывая загрузку остальных.

## Дополнительные команды

```text
python app.py --data-dir "D:\MyHistory" --pck "D:\SteamLibrary\steamapps\common\Slay the Spire 2\SlayTheSpire2.pck"
python app.py --port 9000
python app.py --check
python -m unittest -v
```

Папка может быть корнем SlayTheSpire2, Steam-профиля или конкретной папкой history. Для кооператива путь должен содержать SteamID владельца.

## Разработка

```text
python desktop.py
python -m unittest discover -s . -v
```

Для запуска исходников не нужны сторонние Python-библиотеки. Тесты используют синтетические данные и не изменяют историю игры. Временные данные тестов создаются в `.test-work/`.

В репозитории нет сохранений, истории забегов или настроек конкретного пользователя. При запуске источники определяются на компьютере пользователя. Лицензии сторонних компонентов находятся в `licenses/`.
